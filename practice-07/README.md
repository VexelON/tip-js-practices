## 2. Компоненты и состояние

`App` владеет `tasks`, `filters` и `editingId`. Вниз передаются данные, вверх — `onToggle` / `onEdit` / `onDelete` / `onSave` / `onChange`. `TaskForm` хранит черновик и ошибки. Выборка и статистика считаются на каждом рендере: `selectTasks(tasks, filters)` и `getTaskStats(tasks)`.

Обновления неизменяемые: `addTask` / `updateTask` / `toggleTask` / `removeTask` возвращают новый массив. Ключ карточки — `task.id`. Форма пересоздаётся `key={editingId ?? "new"}`. Подтверждение удаления вызывается до `setTasks`, чтобы `confirm` не оказался внутри updater.

## 6. Контрольные вопросы

1. JSX — выражения дерева элементов, а не строка HTML.
2. Props приходят снаружи; состояние принадлежит компоненту.
3. Обычная переменная сбрасывается на каждом вызове функции.
4. Когда новое значение зависит от предыдущего.
5. Иначе несколько ссылок разделят один объект.
6. Стабильный `key` сохраняет тождество элемента; индекс ломается при удалении.
7. Иначе пришлось бы синхронизировать три копии одних данных.
8. Вызывает переданный callback, родитель меняет состояние.
9. `value`/`checked` из состояния плюс `onChange`.
10. Значение `<select>` всегда строка.
11. Смена ключа размонтирует форму и сбрасывает локальное состояние.
12. Побочные эффекты нельзя класть в updater, особенно при StrictMode.
13. Пустой набор и нулевая статистика против «ничего не найдено» при ненулевом `total`.
14. `npm test` проверяет домен, не JSX.
15. Появятся HTTP-клиент, эффекты загрузки, асинхронный `onSave` и обработка ошибок сети.
