## 2. Модель

Категория 1—N задач. Задача обязана ссылаться на существующую категорию (`ON DELETE RESTRICT`). Пустая категория допустима. Название категории хранится один раз. `btrim` и `char_length` отклоняют, а не исправляют пробелы и длину.

Identity `BY DEFAULT` позволяет вставить прежние id 1…34, затем `setval(max(id), true)` даёт следующий id 35 / 4.

## 5. Контрольные вопросы

1. PRIMARY KEY идентифицирует строку; UNIQUE запрещает повтор значения без обязательности быть единственным ключом сущности.
2. CHECK не запрещает NULL, поэтому нужен NOT NULL.
3. RESTRICT сохраняет задачи и запрещает удалить занятую категорию.
4. BY DEFAULT позволяет явно задать учебные id.
5. Явный INSERT не двигает identity — нужен setval.
6. Последовательность не откатывается вместе со строками.
7. LEFT JOIN + count(t.id) сохраняет пустые категории.
8. WHERE фильтрует строки, HAVING — группы.
9. ORDER BY делает порядок воспроизводимым.
10. btrim/char_length и JS trim/length считают пробелы и символы по-разному.
11. `%` и `_` в LIKE — шаблоны, в includes — обычные символы.
12. Проверки схемы идут в транзакции с ROLLBACK; строки возвращаются, sequence может уйти вперёд.
13. Повтор схемы в заполненной базе должен упасть, а не молча пропустить расхождение.
14. Дамп фиксирует текущее состояние, скрипты — намерение схемы.
15. API пока в памяти: без ПР12 сервер базу не читает.
