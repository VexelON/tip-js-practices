### Исправление эксперимента 2

Исходный код стартового комплекта:

```js
const square = (value) => {
  value * value;
};
```

Фактический результат до исправления: `square(4) = undefined | тип: undefined`.

Исправление — добавлен `return`:

```js
const square = (value) => {
  return value * value;
};
```

Фактический результат после исправления: `square(4) = 16 | тип: number`.

Остальные пять экспериментов не изменялись: они демонстрируют поведение языка, а не дефекты
приложения.

## 4. Модель и распределение ответственности

Модель задачи: `{ id, title, completed, priority }`, где `id` — положительное безопасное целое
(уникальное в списке), `title` — нормализованная строка длиной 1…100, `completed` — логическое
значение, `priority` — строго `"low"`, `"medium"` или `"high"`.

| Файл | Ответственность |
|---|---|
| `src/data.js` | Экспорт общего набора `demoTasks`, `variantNumber` и `variantTasks`. Функций изменения, сценариев и вывода нет. |
| `src/task-service.js` | Девять прикладных функций: проверки полей и операции над **переданными** данными. Нет `console.log`, DOM, импорта `demoTasks` и глобального изменяемого списка. |
| `src/task-extra.js` | Расширение: `getPrioritySummary`. Контракты девяти обязательных функций не меняются. |
| `src/main.js` | Импорт модулей, последовательность действий, вывод и обработка отказов. Поиск, фильтрация и расчёт сводки не дублируются. |
| `checks.js` | Готовые 35 проверочных сценариев. |
| `checks-own.js` | Пять собственных случаев. |

Соглашение о результате: операции создания и изменения возвращают `{ ok: true, ... }` либо
`{ ok: false, error: "..." }`. Ожидаемые отказы — это данные, а не исключения. Для чтения
используются более простые результаты: объект, массив или объект сводки; отсутствие записи при
поиске обозначается `undefined`.

**Как проверялось отсутствие мутации.** До вызова снимается `JSON.stringify(tasks)`, после вызова
сравнивается с ним же. Дополнительно сравниваются ссылки: `result.tasks !== tasks` и
`result.tasks[index] !== tasks[index]` для изменённой записи, `===` — для неизменённых. Одного
сравнения массивов недостаточно: массив может быть новым, а объект внутри — испорченным.

Для добавления используется spread массива, для обновления — `map` и spread объекта, для
удаления — `filter`. `push`, `splice` и присваивания свойствам входных объектов не применяются.

между запусками.

## 10. Дополнительное задание. Вариант Б — сводка по приоритетам

Контракт: `getPrioritySummary(tasks)` возвращает объект

```js
{ low: { total, pending }, medium: { total, pending }, high: { total, pending } }
```

Для каждого приоритета считаются общее количество задач и количество невыполненных. Все три
приоритета присутствуют в результате, даже если соответствующих задач нет. Исходный массив и его
объекты не изменяются: используется только `filter` без присваиваний свойствам.

Фактические результаты (случай 5 собственных проверок):

| Набор | Ожидание | Факт |
|---|---|---|
| `demoTasks` | `low 1/1`, `medium 2/0`, `high 1/1` | Совпало |
| `[]` | Все шесть чисел равны нулю | Совпало |
| Список из двух задач одного приоритета | `high 2/1`, остальные нули | Совпало |
| `variantTasks` | `low 2/1`, `medium 2/0`, `high 2/0` | Совпало (вывод `npm start`) |

## 11. Вывод

Логика приложения выделена в девять функций с явными контрактами: аргументы, результат и поведение
при ошибке описаны независимо от реализации, поэтому проверки не зависят от того, как именно
написан код. Главный практический вывод — различие двух уровней копирования: новый массив ещё не
означает независимые записи, поэтому при изменении одной задачи создаётся и новый массив, и новый
объект выбранной записи, а нетронутые объекты переиспользуются. Второй вывод — ожидаемый отказ
операции и ошибка в самой программе разделены: первый возвращается как данные `{ ok: false }` и
не прерывает сценарий, второй остался бы исключением.

Подготовленный модуль не содержит `console.log` и обращений к DOM, поэтому в ПР3 его можно вызвать
из обработчика события на странице без изменения кода.
