## 4. Задание 1. Один файл — две среды выполнения

Файл `js/hello.js` запущен двумя способами без изменения кода.

| Среда | Как запущен | Где появился вывод | Последняя строка |
|---|---|---|---|
| Node.js | `node practice-01/js/hello.js` из корня репозитория | Терминал | `Тип document: undefined` |
| Браузер | Открыт `practice-01/index.html`, вкладка Console | Консоль DevTools, **не на странице** | `Тип document: object` |

Фактический вывод в Node.js:

```text
Студент: Учебный студент
Группа: Учебная группа
Практическая работа: 1
JavaScript успешно запущен
Тип document: undefined
```

**Объяснение различия.** JavaScript — язык, Node.js и браузер — разные среды выполнения.
Браузер предоставляет объект `document` как точку входа в DOM страницы, поэтому `typeof document`
даёт `"object"`. Обычный запуск файла через Node.js не создаёт HTML-документ и браузерный DOM,
глобальная переменная `document` не объявлена, поэтому `typeof` возвращает `"undefined"` —
без исключения, потому что `typeof` безопасен для необъявленных идентификаторов.

На HTML-страницу текст не выводился: `console.log()` пишет только в консоль.

## 5. Задание 2. Исследование типов и преобразований

Команда: `node practice-01/js/types.js`. Тот же файл проверен в браузере — результаты совпали.

| № | Выражение | Ожидание до запуска | Фактическое значение | Тип результата | Объяснение |
|---:|---|---|---|---|---|
| 1 | `"8" + 2` | `"82"` | `82` (строка) | `string` | Если хотя бы один операнд `+` — строка, выполняется конкатенация, а не сложение: число `2` приводится к `"2"`. |
| 2 | `"8" - 2` | `6` | `6` | `number` | У оператора `-` нет строковой перегрузки, поэтому оба операнда приводятся к числу. |
| 3 | `Number("8") + 2` | `10` | `10` | `number` | Явное преобразование выполнено до сложения, оба операнда числа. |
| 4 | `"12" > "3"` | `false` | `false` | `boolean` | Две строки сравниваются посимвольно по кодовым единицам: `"1"` < `"3"`, длина не учитывается. |
| 5 | `12 === "12"` | `false` | `false` | `boolean` | Строгое равенство не приводит типы; `number` и `string` не равны. |
| 6 | `Number("")` | `0` | `0` | `number` | Пустая строка (как и строка из пробелов) преобразуется в `0`, а не в `NaN`. Поэтому `Number()` сам по себе не является проверкой ввода. |
| 7 | `Number("text")` | `NaN` | `NaN` | `number` | Непреобразуемая строка даёт `NaN`, при этом тип результата остаётся `number`. |
| 8 | `Boolean("false")` | `true` | `true` | `boolean` | Логическое преобразование не читает содержимое текста: любая непустая строка истинна. |
| 9 | `typeof null` | `"object"` | `object` | `string` (тип самого результата `typeof`) | Историческая особенность языка: `null` — примитив, но `typeof` возвращает для него `"object"`. Сам результат `typeof` всегда строка. |
| 10 | `typeof NaN` | `"number"` | `number` | `string` (тип самого результата `typeof`) | `NaN` принадлежит типу `number`, поэтому `typeof value === "number"` не доказывает корректность числа. |

Фактический вывод:

```text
1) "8" + 2 = 82 | тип: string
2) "8" - 2 = 6 | тип: number
3) Number("8") + 2 = 10 | тип: number
4) "12" > "3" = false | тип: boolean
5) 12 === "12" = false | тип: boolean
6) Number("") = 0 | тип: number
7) Number("text") = NaN | тип: number
8) Boolean("false") = true | тип: boolean
9) typeof null = object | тип самого результата: string
10) typeof NaN = number | тип самого результата: string
```

Расхождений между прогнозом и фактом не было.

## 6. Задание 3. Сводка выполнения задач

Файл `js/progress.js`. Проверка выполняется в порядке: тип → целочисленность → границы →
соотношение `completedTasks <= totalTasks`. Только после этого считается процент, поэтому деления
на ноль не происходит: случай `totalTasks === 0` обрабатывается отдельной веткой.

| Проверка | Входные данные | Ожидаемый результат | Фактический результат | Итог |
|---|---|---|---|---|
| Обычный случай | `12`, `5` | Осталось 7; `41.7%`; «В работе» | `Осталось: 7`, `Прогресс: 41.7%`, `Статус: В работе` | Пройдено |
| Нет задач | `0`, `0` | «Задач пока нет», процент не считается | `Задач пока нет` | Пройдено |
| Ничего не выполнено | `5`, `0` | Осталось 5; `0.0%`; «Не начато» | `Осталось: 5`, `Прогресс: 0.0%`, `Статус: Не начато` | Пройдено |
| Всё выполнено | `5`, `5` | Осталось 0; `100.0%`; «Завершено» | `Осталось: 0`, `Прогресс: 100.0%`, `Статус: Завершено` | Пройдено |
| Выполнено больше, чем есть | `5`, `6` | Ошибка | `Ошибка: выполнено больше задач, чем существует.` | Пройдено |
| Отрицательное количество | `-1`, `0` | Ошибка | `Ошибка: общее количество задач не может быть отрицательным.` | Пройдено |
| Дробное количество | `5`, `2.5` | Ошибка | `Ошибка: количество выполненных задач должно быть целым числом.` | Пройдено |
| Строка вместо числа | `"5"`, `2` | Ошибка | `Ошибка: общее количество задач должно быть числом.` | Пройдено |
| Верхняя граница | `1001`, `0` | Ошибка | `Ошибка: общее количество задач не должно превышать 1000.` | Пройдено |
| Недопустимое число | `NaN`, `0` | Ошибка | `Ошибка: общее количество задач должно быть числом.` | Пройдено |
| **Свой вариант 6** | `18`, `6` | Осталось 12; `33.3%`; «В работе» | `Осталось: 12`, `Прогресс: 33.3%`, `Статус: В работе` | Пройдено |

Фактический вывод для варианта (текущее состояние файла):

```text
Всего задач: 18
Выполнено: 6
Осталось: 12
Прогресс: 33.3%
Статус: В работе
```

Значение `NaN` отклоняется не оператором `typeof` (он даёт `"number"`), а проверкой
`Number.isFinite()`. Строка `"5"` отклоняется до любых арифметических операций, автоматического
преобразования в решении нет.

## 7. Задание 4. План выполнения задач по дням

Файл `js/plan.js`. План строится по **оставшимся** задачам. Цикл `while` на каждой итерации
увеличивает номер дня, берёт `Math.min(dailyLimit, remainingTasks)` и уменьшает остаток, поэтому
остаток монотонно убывает и не становится отрицательным, а последний день может быть неполным.
При недопустимых данных цикл не запускается вовсе.

| Проверка | Входные данные | Ожидаемый результат | Фактический результат | Итог |
|---|---|---|---|---|
| Обычный случай | `12`, `5`, `3` | 3 дня, в последний день 1 задача | `День 3: выполнено 1, осталось 0`, `Потребуется дней: 3` | Пройдено |
| Ровное деление | `10`, `4`, `3` | 2 дня по 3 задачи | `Потребуется дней: 2` | Пройдено |
| Лимит больше остатка | `5`, `3`, `10` | 1 день, выполнено 2 | `День 1: выполнено 2, осталось 0`, `Потребуется дней: 1` | Пройдено |
| Всё выполнено | `5`, `5`, `2` | 0 дней, цикл не выполняется | `Все задачи уже выполнены`, `Потребуется дней: 0` | Пройдено |
| Пустой список | `0`, `0`, `2` | 0 дней | `Потребуется дней: 0` | Пройдено |
| Нулевая норма | `5`, `2`, `0` | Ошибка, цикл не запускается | `Ошибка: дневная норма должна быть не меньше 1.` | Пройдено |
| Дробная норма | `5`, `2`, `1.5` | Ошибка | `Ошибка: дневная норма должна быть целым числом.` | Пройдено |
| Неверное `completedTasks` | `5`, `6`, `2` | Ошибка | `Ошибка: выполнено больше задач, чем существует.` | Пройдено |
| Норма строкой | `5`, `2`, `"2"` | Ошибка | `Ошибка: дневная норма должна быть числом.` | Пройдено |
| Верхняя граница нормы | `5`, `2`, `1001` | Ошибка | `Ошибка: дневная норма не должна превышать 1000.` | Пройдено |
| **Свой вариант 6** | `18`, `6`, `5` | 3 дня: 5, 5, 2 | см. вывод ниже | Пройдено |

Фактический вывод для варианта (текущее состояние файла):

```text
Осталось задач: 12
День 1: выполнено 5, осталось 7
День 2: выполнено 5, осталось 2
День 3: выполнено 2, осталось 0
Потребуется дней: 3
```

Проверка `dailyLimit` выполняется даже при нулевом остатке: иначе некорректная норма прошла бы
незамеченной, а при `dailyLimit = 0` остаток никогда не уменьшался бы и цикл стал бы бесконечным.

## 9. Дополнительное задание. Вариант Б — план с выходными днями

## 10. Вывод

Освоен базовый цикл разработки: написать код, запустить его в двух средах, проверить обычные,
граничные и некорректные данные, найти причину расхождения и зафиксировать изменения в Git.

Наиболее показательной оказалась ошибка в `debug.js`: программа завершалась без исключения и
выводила правдоподобные числа, хотя складывала строки. Один итоговый `console.log()` показывает
только результат, тогда как точка останова показывает **тип** промежуточного значения до того, как
оно попадёт в следующую операцию. Второй полезный вывод — `typeof value === "number"` недостаточно
для проверки количества: `NaN` проходит такую проверку, поэтому в решениях используются
`Number.isFinite()` и `Number.isInteger()`, а затем отдельно проверяются границы диапазона.
